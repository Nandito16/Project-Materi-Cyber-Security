Jaga Pintu Login dari Kata Ajaib!

SQL Injection adalah trik menulis “kata ajaib” di kotak login untuk menipu database supaya membuka pintu tanpa sandi yang benar. Di sini kamu belajar cara kerjanya — dan cara developer menutup celahnya.

Aturan Main — Baca Dulu!

⚠️ Mencoba “kata ajaib” di website orang lain tanpa izin itu DILARANG

  1. Selalu minta izin dulu. Mencoba menembus login milik orang lain bisa melanggar hukum — sama seperti mencoba-coba membuka gembok rumah tetangga.
  2. Hanya berlatih di kotak login milikmu sendiri — atau di halaman latihan khusus seperti ini yang memang dibuat untuk belajar.
  3. Jangan pernah mencoba trik ini di website sungguhan, sekolah, game, atau toko online. Itu bukan lelucon.
  4. Kalau kamu menemukan celah, laporkan. Beri tahu pemilik website atau orang dewasa. Jangan diutak-atik, jangan disebar.
  5. Ilmu ini untuk menutup celah, bukan membobol. Developer yang baik memakainya untuk memperkuat pintunya sendiri.

Apa Itu SQL Injection?

🗄️ Database itu apa?

Website menyimpan data pemain (nama & sandi) di sebuah gudang data bernama database. Saat kamu login, website bertanya ke gudang: “Apakah ada pemain bernama X dengan sandi Y?”

Pertanyaan itu ditulis dalam bahasa khusus bernama SQL. Contohnya kira-kira begini:

Perintah SQL saat kamu login
SELECT * FROM pemain WHERE nama='budi' AND sandi='rahasia'
Idenya: perintah ini seharusnya hanya cocok kalau nama dan sandi benar.

🎭 Kata ajaib yang menipu

Masalah muncul kalau website menempel ketikanmu apa adanya ke dalam perintah. Penjahat menulis nama yang mengandung tanda kutip dan syarat palsu:

Yang diketik penjahat di kolom nama
admin' OR '1'='1

Tanda kutip ' menutup nama lebih awal, lalu OR '1'='1' menambah syarat yang selalu benar. Akibatnya database mengira semua pemain cocok, dan pintu terbuka tanpa sandi.

Analogi: seperti menulis di kartu tamu “Nama saya Budi — ATAU siapa saja boleh masuk”, dan penjaga menurutinya bulat-bulat.

Cara Melindungi Pintu Login

CaraPenjelasan
Parameterized query
(pertahanan utama)		 Kirim perintah dan data secara terpisah (pakai tanda ?). Ketikan pengguna tidak akan pernah dianggap sebagai perintah. Ini menutup hampir semua SQL Injection.
Periksa masukan
(validasi)		 Tolak karakter aneh di tempat yang seharusnya tidak ada, dan pastikan bentuk data sesuai (misalnya umur harus angka).
Beri hak seperlunya Akun database untuk website cukup diberi izin yang perlu saja, supaya kalaupun bocor, kerusakannya terbatas.
Simpan sandi teracak
(hashing)		 Sandi jangan disimpan apa adanya, tapi diacak dulu. Kalau gudang data bocor, sandinya tetap sulit dibaca.
Sembunyikan pesan error Jangan tampilkan pesan error database ke pengunjung — itu bisa membocorkan bentuk perintahnya (ingat materi Kebocoran Informasi).
